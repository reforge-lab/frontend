## What this is

Reforge Frontend is the Next.js and Fumadocs-powered web documentation platform for Reforge. It serves rich interactive documentation to human readers and structured, clean Markdown/text feeds (`llms.txt`, `llms-full.txt`, and HTTP content negotiation) to AI coding assistants and LLMs.

## Key Patterns

**Adding or editing documentation:**
1. Create or edit MDX files in `content/docs/` (e.g., `content/docs/getting-started.mdx`).
2. Add YAML frontmatter with `title` and `description`.
3. Fumadocs automatically detects and includes the new page in the page tree (`source.getPageTree()`).

**Custom MDX components:**
- Define or register custom MDX components in `src/components/mdx.tsx` using `getMDXComponents()`.
- Default Fumadocs UI components (`Cards`, `Card`, `Callout`, etc.) are imported from `fumadocs-ui/mdx`.

**Content negotiation & LLM endpoints:**
- `proxy.ts` intercepts requests with `Accept: text/markdown` or `.md` suffixes and rewrites them to `/llms.mdx/docs/[...slug]/content.md`.
- `/llms.txt` provides the index summary for LLMs.
- `/llms-full.txt` compiles all doc pages into a single full text document.

**Styling & UI:**
- Utility classes are combined using `cn()` from `@/lib/cn`.
- Global layout wrapper uses `RootProvider` from `fumadocs-ui/provider/next`.

## Glossary

| Term | Definition |
| --- | --- |
| Source Loader | The Fumadocs `loader()` instance in `src/lib/source.ts` providing typed access to MDX content. |
| Page Tree | The hierarchical structure generated by Fumadocs representing navigation and sidebar items. |
| Content Negotiation | Proxy-level rewriting in `proxy.ts` that serves raw markdown when requested by agents/crawlers. |
| MDX Collection | Documents configured via `defineDocs` macro from `content/docs`. |

## Key Invariants

- All documentation content must live inside `content/docs/`.
- Every MDX file in `content/docs/` must contain valid frontmatter (`title`, `description`).
- Strict TypeScript must pass without errors (`npm run types:check`).
- Shared application metadata (repo URL, app name) must be configured in `src/lib/shared.ts`.
- MDX relative links must use `createRelativeLink(source, page)` to preserve routing integrity.

---

## What NOT to do

- Do not hardcode GitHub links or navigation routes across individual pages — use `src/lib/shared.ts` and `src/lib/layout.shared.tsx`.
- Do not bypass `proxy.ts` or disable content negotiation headers.
- Do not import client-only hooks directly in server components inside `src/app/docs/[[...slug]]/page.tsx`.
- Do not create custom CSS stylesheets when Tailwind v4 classes or Fumadocs theme variables can be used.

## Development Workflow

```bash
npm install           # Install dependencies
npm run dev           # Start development server on http://localhost:3000
npm run build         # Production build (Next.js & Fumadocs static compilation)
npm run lint          # Run ESLint
npm run types:check   # Run Next.js typegen and TypeScript type checking
```

Before committing: `npm run lint` and `npm run types:check` must pass.

## Gotchas

- **Fumadocs MDX Macro**: Next.js config uses Fumadocs MDX plugins. If types are out of sync after adding MDX files, run `npm run types:check` to regenerate Next.js typegen and verify types.
- **Git Config in Shared**: `src/lib/shared.ts` contains placeholder values for `gitConfig` (`fuma-nama/fumadocs`). Ensure this is updated to point to the actual Reforge GitHub repo.
- **Port Conflicts**: Next dev runs on port 3000 by default; ensure no other instances are holding port 3000.
